Android-shell overlay — files that survive `npx cap add android` regeneration.

`capacitor/android/` is generated by Capacitor and gitignored, so any changes
made there are lost the next time `cap add android` runs on a fresh checkout.
This directory holds the source files we own (custom `MainActivity.kt`, the
Go-process service, gradle snippets, native-binary jniLibs) and is copied
over the freshly-generated tree by `../apply-overlay.sh`.

Layout
------
- `app/src/main/jniLibs/<abi>/libmedtracker.so` — produced by
  `scripts/build-android-binaries.sh` (gitignored — see `.gitignore`).
  Android's packager extracts `lib*.so` files from `jniLibs/<abi>/` into the
  per-app `nativeLibraryDir` at install time, which gives us a read-only
  executable location to spawn the Go binary from. The name "libmedtracker.so"
  is required by that extraction rule even though the file is a regular ELF
  executable, not a shared library.

Future tasks (per the Phase 2a plan) will add under this tree:
- `app/src/main/java/.../MainActivity.kt` — overrides Capacitor's default to
  spawn the Go binary before `loadUrl`. (Task 3)
- `app/src/main/java/.../GoServerService.kt` — foreground service that owns
  the `Process` handle and reads the `LISTENING 127.0.0.1:<port>` line from
  stdout. (Task 3)
- `app/src/main/AndroidManifest.xml` snippet — declares the foreground
  service + `<application android:extractNativeLibs="true">` so the binary
  ends up on disk, not mmap'd inside the APK. (Task 3)

Workflow
--------
After `npx cap add android` (or anytime the overlay changes):

    ./scripts/build-android-binaries.sh    # produces the per-ABI .so files
    cd capacitor && ./apply-overlay.sh     # copies overlay into android/

The overlay copy is idempotent — repeated runs just overwrite. The Go
binaries are large (~13 MB stripped per ABI), so they are deliberately
excluded from git and re-built locally.
