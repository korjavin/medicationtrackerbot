# Demo Mode (public, auth-less, AI-rate-limited)

## Overview

Add a `DEMO_MODE=1` runtime flag that lets us deploy the same server binary as a public, browseable demo. In demo mode:

1. **No Telegram bot** — already covered: `cmd/bot/main_server.go:48-51` already logs "web-only mode" and skips bot construction when `TELEGRAM_BOT_TOKEN` is empty. The demo just doesn't set it. No code change needed here.
2. **No web auth** — `/api/*` is fully public. Every request resolves to a single fixed demo user (the seeddemo target) instead of going through Telegram-initData / OIDC.
3. **No MCP auth** — the MCP server (separate `cmd/mcptool` binary, `internal/mcp`) skips the Pocket-ID OAuth middleware so any client can connect to `/mcp` and `/sse`.
4. **Restrictive per-IP rate limits on AI-cost endpoints** so a few visitors can't drain our OpenAI / ElevenLabs budget:
   - `GET /api/elevenlabs/signed-url` + `POST /api/elevenlabs/upload-file` ("call the voice agent") → **1 per IP per day**
   - `POST /api/food/log/from-photo` ("log food from photo", vision) → **1 per IP per hour**
   - `POST /api/food/log/from-description` ("log food from text", text-completion) → **1 per IP per hour**
   - `POST /api/food/log` ("log food" — manual, hits no AI) → **1 per IP per hour** (per user's request; matches the food-log throttle)
   All limits configurable via env vars with the values above as defaults.
5. **Frontend "Demo version" affordance** — a dismissible banner on first load explaining "this is a public demo, data is shared and may reset, AI features are rate-limited"; the 429 path on any rate-limited endpoint surfaces a clear popup that quotes the demo restriction rather than the generic "Too Many Requests".

This is the natural pair to the existing single-user mobile build (`//go:build mobile`, `LocalUserResolver`) — they share the same "trust everything, one fixed user" shape — but kept as a **runtime flag, not a build tag** so we ship one binary and toggle demo at the docker-compose level. The `seeddemo` CLI (`cmd/seeddemo`) already populates a deterministic 90-day dataset for a given user, and is the intended way to fill the demo database.

## Technical Details

**Env vars added** (defaults shown):
- `DEMO_MODE=0` — master switch.
- `DEMO_AGENT_CALLS_PER_DAY=1` — combined limit for both ElevenLabs routes.
- `DEMO_FOOD_LOGS_PER_HOUR=1` — manual food log throttle.
- `DEMO_FOOD_PHOTOS_PER_HOUR=1` — vision endpoint throttle.
- `DEMO_FOOD_DESCRIPTIONS_PER_HOUR=1` — text-completion endpoint throttle.
- `AUTH_TRUST_PROXY` — already exists, must be `1` for the demo deployment behind Traefik.

**Rate-limit data shape** (response body on 429):
```json
{"error":"demo_rate_limit","limit":"food_log","retry_after_seconds":3600}
```
Plus `Retry-After: 3600` header.

**Bootstrap addition** (when `DEMO_MODE=1`):
```json
{
  "demo": {
    "enabled": true,
    "limits": {
      "agent_calls_per_day": 1,
      "food_logs_per_hour": 1,
      "food_photos_per_hour": 1,
      "food_descriptions_per_hour": 1
    }
  }
}
```

**Auth resolver behavior** (server build, demo mode):
- Every `/api/*` request resolves to `auth.User{ID: cfg.AllowedUserID, FirstName: "Demo"}` regardless of headers/cookies.
- The `allowedUserID` must be the same user the operator targeted with `cmd/seeddemo` to populate the demo DB.

**MCP behavior** (demo mode):
- `s.oauth` is nil; `Run()` mounts the bare `streamableHandler` / `sseHandler` on `/mcp` and `/sse`.
- `/.well-known/oauth-protected-resource` is not mounted.
- The `mcp_execute` Python runner path still works because it goes through the in-process executor + bridge (`internal/server/mcp_bridge.go`), which uses `cfg.MCP.AuditSecret`, not OAuth.

**Build seam check**: demo mode is a runtime flag, not a build tag. The single server binary supports both production and demo deployments via `DEMO_MODE`. The mobile build (`//go:build mobile`) is untouched and unaware of demo mode. No new build tags introduced.
