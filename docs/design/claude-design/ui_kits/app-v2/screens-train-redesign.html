Answers to the open questions

  1. A or B? I recommend A. It leaves the approved Timeline exactly as it is and puts every record 2 taps away. B is faster for your latest PRs, but it lengthens the Timeline and hides the trends behind a page.
  2. Records data: both options show what the exercise page already computes (best set, est. 1RM, PR date), listed across lifts, with no new metric and no stored-shape change. The cross-lift list is a derived read, which is Archie’s to place in web/domain/workout.js.
  3. Deeplinks: no deeplink, reminder or MCP link names a Train sub-tab (only ?tab=workouts), so only the stored mt-workouts-subtab needs its old values mapped.
  4. Build: one screen per PR. For A: (1) the strip + Progress records, (2) the Library rows in Plans. For B: (1) the records card, (2) the Progress page + the strip, (3) the Library rows.
