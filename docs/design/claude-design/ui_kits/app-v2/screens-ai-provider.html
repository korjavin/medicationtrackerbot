AI provider

Epic med-ezux, bead med-ezux.2. The AI section read as OpenAI-only, so an Anthropic key had nowhere obvious to go. The provider now comes first, with presets for OpenAI, Anthropic, Gemini and OpenRouter, and Other for any URL. Stored data doesn't change: the provider is read from the saved URL. Replaces the OpenAI card on Settings → AI & integrations.

Answers to the open questions

Developer, 2026-10-29: all as recommended, AP6 included.

  • Pick the provider: a row with the value plus the choice dialog (AP1, AP2), not five rows on an already long page.
  • Check key: checks the fields as typed only when this page already permits the target origin, one tiny request to the chosen model, saves nothing (AP3, AP3b). For a new host, AP3c requires explicit Save and a page reload before checking. Saving is not a successful check. Product amendment: Miles 9421/9447, 2026-10-30; security requirements from Socrates 9442 apply. Every first setup, including OpenAI, may need Save → reload → Check key. Save only stores settings; a check proves one small real request works.
  • Unavailable check capability: if the current app document cannot establish permission (including an older shell), keep Check key disabled and show a neutral note: "Key checking is unavailable in this app version. Update the app to check your key." Do not mark the URL invalid or suggest Save/reload. Keep existing settings editable and Save available when valid; existing AI use is unaffected. This is a capability note, not the AP3e invalid-URL field error (Archie 9475).
  • Reusing a saved key: changing the API base with an untouched masked key requires re-entry: "Enter your API key again for this API URL." Never send the old key to the changed base. Check is disabled until the key is entered; this is neither an invalid-key response nor a permission success. No Check button is added under Advanced; the new UI checks the main provider only.
  • Switching with a saved key: the key field empties, Save waits for a new key, the old key never goes to the new provider (AP6).
  • New Gemini preset example, 2026-10-30: use gemini-3.8-flash for a new/unset preset. Google’s current OpenAI-compatible example uses it; 2.5 Flash is restricted to prior active users. This is not a migration: preserve every saved/custom model, including gemini-2.5-flash. Existing explicit selection/fill rules still apply; no rewrite on load and no app-certification claim.
  • Model: a preset fills its recommended model and saves it explicitly; Choose still lists the provider's models.
  • Old settings: api.openai.com or blank → OpenAI, a preset URL → that preset, anything else → Other with the URL (AP4). Nothing is rewritten on open.
  • Get an API key opens the provider's key page in the browser.
  • Also: the trial's "Your own keys" row reads "AI provider" (value: Not set / Set), and the Settings home line names the chosen provider ("Anthropic · Voice").
