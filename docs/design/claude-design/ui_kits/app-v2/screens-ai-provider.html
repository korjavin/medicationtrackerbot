AI provider

Epic med-ezux, bead med-ezux.2. The AI section read as OpenAI-only, so an Anthropic key had nowhere obvious to go. The provider now comes first, with presets for OpenAI, Anthropic, Gemini and OpenRouter, and Other for any URL. Stored data doesn't change: the provider is read from the saved URL. Replaces the OpenAI card on Settings → AI & integrations.

Answers to the open questions

Developer, 2026-10-29: all as recommended, AP6 included.

  • Pick the provider: a row with the value plus the choice dialog (AP1, AP2), not five rows on an already long page.
  • Committed reload (final Archie 10341, presentation accepted): AP3d · committed Reloading / committed retry reuse the existing dialog styling. Preparation stays cancellable; after the final synchronous dirty check and irreversible activation request, keep the app inert until safe fresh navigation. Bounded wait exhaustion shows a Reload page action, never “failed, keep editing”. No auto-save, implicit draft loss or permanent busy-only surface. Late matching claim immediately owns one marked navigation; network-fresh failure replaces the app with the existing non-app retry document. These are scoped provider-reload states, not a general update redesign.
  • Check key: checks the fields as typed only when this page already permits the target origin, one tiny request to the chosen model, saves nothing (AP3, AP3b). For a new host, AP3c requires explicit Save and a page reload before checking. Saving is not a successful check. Product amendment: Miles 9421/9447, 2026-10-30; security requirements from Socrates 9442 apply. Every first setup, including OpenAI, may need Save → reload → Check key. Save only stores settings; a check proves one small real request works.
  • Unavailable check capability: if the current app document cannot establish permission (including an older shell), keep Check key disabled and show a neutral note: "Key checking is unavailable in this app version. Update the app to check your key." Do not mark the URL invalid or suggest Save/reload. Keep existing settings editable and Save available when valid; existing AI use is unaffected. This is a capability note, not the AP3e invalid-URL field error (Archie 9475).
  • Reusing a saved key: changing the API base with an untouched masked key requires re-entry: "Enter your API key again for this API URL." Never send the old key to the changed base. Check is disabled until the key is entered; this is neither an invalid-key response nor a permission success. No Check button is added under Advanced; the new UI checks the main provider only.
  • Switching with a saved key: the key field empties, Save waits for a new key, the old key never goes to the new provider (AP6).
  • New Gemini preset example, 2026-10-30: use gemini-3.8-flash for a new/unset preset. Google’s current OpenAI-compatible example uses it; 2.5 Flash is restricted to prior active users. This is not a migration: preserve every saved/custom model, including gemini-2.5-flash. Existing explicit selection/fill rules still apply; no rewrite on load and no app-certification claim.
  • Model: a preset fills its recommended model and saves it explicitly; Choose still lists the provider's models.
  • Other credentials, corrected 2026-10-30 (Archie 9915): new/switched Other requires a URL and an explicit key. Missing URL: “Enter your provider’s API URL before saving.” Missing key: “Enter an API key for this provider before saving.” Use the existing field hints; disable Save while missing, keep fields editable. Preserve legacy saved keyless data on load, with no runtime/trial behavior changes. The old optional-key claim and appearance approvals are superseded.
  • Photo credential binding (Archie 9920): AP5a keeps the old effective photo URL/model with an explicit saved photo key when main changes. AP5b blocks a retained different-origin photo URL from borrowing a new main key. AP5c requires key re-entry at an edited photo base. Use the existing Advanced fields and inline hints; reveal Advanced for a blocking review. Fully inherited photo key+URL follow main normally. Explicit/model-only edits remain authoritative. Automatic preservation pins belong only to retained saved photo masks and remain draft-only until Save. Replacing/clearing the credential unwinds only still-owned, untouched pins equal to their generated values and clears their hints before binding a replacement. An explicit field edit retires its automatic ownership even when its text equals the generated value; explicit edits remain authoritative. Typed photo keys bind once at explicit entry/re-entry to their then-effective normalized base; later form changes never relearn that binding. Retargets reuse AP5c, retaining typed text while blocking Save. Track only public base/provenance, never duplicate raw keys/hashes or stored fields. Only moving the effective photo endpoint away from its bound base retires untouched old model pins/hints; a same-base/no-op URL event alone does not. Deliberate custom models survive clearing. Preserve the exact raw prior effective URL in draft/PATCH pins, including path/trailing slashes; normalization is comparison-only and never replaces the value consumed by the client. Full Back/cancel restores the loaded state; main reselect is not photo re-entry. Mask/failed-read fallback never establishes a saved secret as Set without confirmed stored presence. Failed Save preserves loaded active settings.
  • Draft status and mask precision (Webb 10001): a valid explicit separate-photo draft says “Food photos use separate settings”; confirmed saved-photo retention alone uses “Food photos keep their saved provider”. Fully inherited settings keep the provider-above description and blocked review states keep “Review Photo API key”. A fabricated voice mask with no confirmed saved voice key is rejected before PATCH/cache via the existing safeToast: “Enter your voice API key or clear the field — there is no saved key to keep.” Voice status uses accepted masked settings. Reverting an Other URL restores only an untouched saved mask; never replace a newly entered raw key with a restored mask. No new control/frame, runtime or stored shape.
  • Old settings: api.openai.com or blank → OpenAI, a preset URL → that preset, anything else → Other with the URL (AP4). Nothing is rewritten on open.
  • Get an API key opens the provider's key page in the browser.
  • Also: the trial's "Your own keys" row reads "AI provider" (value: Not set / Set), and the Settings home line names the chosen provider ("Anthropic · Voice").
