Review: what we designed vs what the app does now

The Wandergeek handoff covered 8 screens and 4 modals. The app now has roughly 40 surfaces: Journey, plan/day/exercise editors, per-set logging, equipment, Food DB, photo, scan and describe, meds inventory and timezone plans, AI integrations, and the cloud vault. Almost all of them were built screen by screen. This kit is option B from the audit: shared primitives, plus a rework of the heavy flows. It also proposes a new navigation, shown next to the current one.

Findings beyond the audit

  • Yellow is overspent. Sun fills the primary CTA, the active tab, the active sub-tab, the active segment, the kcal numbers, the eyebrow dots and the Add/Photo/Scan trio, so the real next action is hard to find. Food log shows four filled-yellow controls above the fold. v2 rule: each view gets one sun-filled control. Selection states use raised teal with sun text.
  • Sun on sun is unreadable. The active "Daily total" pill uses sun text on a sun fill. The .wg-seg--accent variant now uses ink text on the sun fill, and the default segment stays teal.
  • Everything is a card of equal weight. Food rows, med rows and metric tiles all use the same card, so a screen reads as a stack of identical boxes. v2: three surface levels (screen, card, accent card), and grouped lists with hairline dividers instead of one card per row.
  • Two square buttons per row cost the title. A pencil and a trash button take about 30% of the row, so "toasted wholegrain br…" gets cut off. v2: tapping the row edits it, swiping left reveals Edit and Delete, and an overflow button is the pointer and keyboard fallback. Titles wrap to two lines.
  • Three navigation layers before any content. The 2-row nav, sub-tabs (5 on Workouts, 4 on Meds) and a toolbar all stack, and no screen has a title. v2: every top-level screen gets an app bar with a title and context. The nav proposal is on the Navigation page.
  • Unstyled native controls. "Tracking incomplete" is a bare checkbox floating under the day nav. The parse-from-description checkbox, file inputs and date inputs are native too. v2: every control is a kit component. "Tracking incomplete" becomes a toggle row with a stale chip on the day.
  • The day navigator breaks on long labels. "Yesterday" pushes over the › button. v2: .wg-daynav uses fixed 44px arrow cells, the label truncates, and the relative day is a chip.
  • Status is spread across emoji, text and colour. Examples: "✅ Taken", "-17 LEFT", "High-normal · stale", and sync tags on only some lists. v2: five semantic status tokens (ok, warn, danger, stale, pending-sync) feed every chip, row state and banner.
  • The voice agent has two control surfaces. Call controls appear in the Today card and again in the floating pill. v2: one call bar. It's compact when idle and becomes the live control strip during a call.

What stays

  • The palette, JetBrains Mono numerals, Space Grotesk UI text and the gloss material.
  • The BP chart and range pills, the Vitals tiles, the Upcoming meds list and the Stats balance bars.
  • Modal headers with Cancel/Save at the top right. You approved this on the Vitals pass, and it keeps Save above the keyboard.

Action placement rule

  • Forms (edit med, BP, weight): Cancel and Save sit in the sheet header or page bar, so they're always above the keyboard.
  • Flows and pickers (add food, take meds, finish workout): the contextual primary ("Add 150 g", "Confirm 3") sits in a footer docked to the top of the keyboard. The header has only a close button.
  • Destructive actions always go through .wg-dialog, never a native confirm.

Implementation constraints honoured

  • Vanilla JS with BEM-ish wg-* classes on --wg-* tokens. Components have no inline styles.
  • The only exception is data-driven values, passed through one custom property (--p for percentages, --n for counts).
  • Icons come from one SVG sprite (icons.js, about 70 original line icons). The kit uses no emoji.
  • Hit targets are at least 44px; set rows use 56px cells.
  • Presentation-only CSS is in kit.css: phone frames, the fake keyboard and the board layout. Don't ship it.
