Exercise names & weight check

Epic med-l5yr. One exercise keeps one history even when it was logged under several names: the library row gets "Also logged as" names, Merge, and a rename that keeps history. Weights that look like a typo get a note under the set. No new components: sheet, list rows, field error, dialog and the warn note are all kit parts.

Answers to the open questions

My recommendations, for Developer to confirm.

  • Where's Merge? At the bottom of the Edit sheet (EI1), not a third icon on every library row. The row keeps Edit and Delete as they are.
  • Names that aren't in the library (Swings, Lateral Raises, Bench Press from Feb): "Add a name from history" in the Edit sheet (EI6) lists the names in your logs that no library row owns. Bulk cleanup goes through the MCP op, so an agent can apply the whole list at once.
  • Merge asks first (EI5), because the merged row's own defaults, equipment and notes go away. Removing a name (× in "Also logged as") doesn't ask, because it only moves the history back under the old name.
  • Rename keeps the history and puts the old name under "Also logged as" (EI2). A change only in letter case adds no name, because matching ignores case. Renaming to a name you already have is blocked, and the field offers the merge instead (EI3).
  • History separation is not a full undo. EI5 says “Remove the name under ‘Also logged as’ to separate its history again.” The removed library row and changed plan links are not restored. Alias last dates keep the recorded calendar day in every viewing timezone (med-dzta, 2026-10-30); no storage or selection changes.
  • Nothing merges by itself. Pairs that must stay distinct (paused vs regular bench, the three cable presses, the deadlifts) stay apart unless you merge them.
  • Weight check, when: a ticked set is more than 2× your heaviest earlier set of that exercise (with at least 3 earlier logs; unconfirmed flagged sets don't count as heaviest), or has kg above 0 on a band or a body-weight exercise in the only log of it with a weight. Only upward jumps are checked. Repeated means real: a flagged weight stops being flagged once a later session logs that exercise at 80% of it or more (sets of the same session don't count), and a band weighted in two sessions isn't flagged. A drop is usually a deload, not a typo.
  • Weight check, what it does: the set is saved as logged. The note sits under the set until you pick Edit or "It's right", or a later session repeats the weight. Until then the set doesn't count toward records or the next target, so a slip can't set a fake PR. The cost: a real jump in your newest session stays flagged until the next one, unless you tap "It's right". Exercise detail has no per-session rows, so a flagged set is reached through History → the session (WS3); confirming happens only there.
  • Old entries: past sessions show the same note when you open them from History (WS3). There's no separate list of them on Stats.
