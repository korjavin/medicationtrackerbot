Answers to the open questions

Decisions (my recommendation, pending Developer)
  1. Where the result lives: one summary row in Basics (ER3), and the full list in a sheet (ER4–ER6). Voltaren alone has 52 rows, which can't sit inline in the editor.
  2. Grouping: one card per distinct substance text as written. Route rows sit under it, each listing all its countries, so every jurisdiction + route row is kept without 52 lines.
  3. "|": a numbered "N products in one entry" list inside the card (ER6), never merged or split into separate entries.
  4. Several entries: the info note "Several register entries match this name. Check the substance on your pack." No selection, no apply.
  5. Countries: chips of the result's own countries, as a sort only (ER5). No chip is preselected; the last tap is remembered on this device.
  6. Settings: "Check names in the EU register" in a new Features → Medications section, subline "Works offline after the first check. Nothing is sent." The bead's long title is shortened for the no-long-descriptions rule (Developer 2026-11-04).
  7. Copy that never appears: anything about the US register, "unknown medicine" or "not authorised".
  8. Footer text comes from the data's source fields (revision, data date, attribution), not hardcoded.
