Answers to the open questions

Approved round 2 (Developer 15503 asked for a US/EU choice in Settings and simpler; approved 15518)
  1. One setting decides the register: "Check names in" US register (default, today's behaviour) or EU register. No editor button, no first-tap opt-in, no on/off switch.
  2. EU chosen: the editor shows an EU chip where the Rx chip is today. The RxNav lookup doesn't run. No interaction warning is lost: RxNav's interaction endpoint is shut down and the client already returns none (rxnorm.js:11-14, Miles 15510).
  3. Sheet: one card per substance text, route rows with countries. No country chips (dropped for simplicity).
  4. Footer: two short lines; the full attribution text stays in the privacy/about page (Miles .5 to confirm it meets the EMA notice).
Slice 2 · open questions, my answers (for Developer)
  1. One match: saved on Save, no extra step, the same as the Rx match today.
  2. Several: nothing is saved until the user taps "Use this" on a card. The app never guesses.
  3. What is stored: the substance text as written, the register revision and its data date (Archie names the fields). The list shows only the substance.
  4. Name changed: the saved EU match goes on Save and a fresh check runs, the same rule as the US match (Miles 15529). Name unchanged: kept.
  5. Switched back to US: the saved EU match stays and still shows; a US match is added beside it on the next save. Nothing the user picked disappears silently.
  6. New register revision: the saved match keeps its own date; no re-check, no warning.
