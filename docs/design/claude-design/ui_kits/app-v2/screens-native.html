Native shells

These screens show before, or instead of, the web app. Each one is designed once and drawn in both shells; only the status bar, the gesture area and the biometric wording change. They use the kit classes as the spec, and SwiftUI and Kotlin mirror them through the token table at the bottom.

Review · v3 shots against kit v2

  • Three visual systems in one launch. iOS shell: teal with system fonts and system blue. Android shell: stock DayNight, white or near-black. Web app: Wandergeek. A cold start on Android goes from a teal splash to a white first run to a teal app (18, 24).
  • No hierarchy in the shells. Android buttons are all identical grey slabs (18, 22, 26). iOS uses .borderedProminent for Continue but a bordered blue pill for the equally important "Only on this device" (01). Neither has a sun primary.
  • The same screen in different orders. First run is invite-first on iOS and local-first on Android. The lock screen shows an SF Symbol on iOS and the launcher icon on Android. Android's error is always "your account", even in local mode, and has no Copy diagnostics.
  • Status off-token. System orange for warnings (iOS), a raw "server answered 503" (22), and errors as plain coloured text instead of field errors (04, 23).
  • Persistent chrome covering actions. The ceremony bar sits over the Emergency Kit's Continue (31). On iOS the tab bar floats mid-screen during the keyboard transition (09). Today's last card is cut by the tab bar (33).
  • Web pages that drifted from the kit. A native checkbox for the loss acknowledgement and wizard-step headings in signup (30, 31). Native <select>s and a truncated title on Notifications (39). Legacy settings rows next to kit rows on Account (40). Settings-home row order depends on mount timing (07 and 35 differ).
  • High-stakes dialogs that all look the same. Erase, delete, replace and move are paragraph-plus-buttons dialogs with no severity, and nothing tells the user what goes and what stays (11, 37, 41, 42, 45).
  • Small text bugs. The 2× font scale clips the placeholder and the footer (20). The filename breaks mid-extension (44). The version shows VERSION_PLACEHOLDER (38).
