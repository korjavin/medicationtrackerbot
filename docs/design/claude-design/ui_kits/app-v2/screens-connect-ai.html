Connect an AI app (Claude Code, Claude, ChatGPT)

Bead med-73xx. “Connect Claude Code” asked people to build a shim from source. It now uses the existing remote connector: one consent, one URL, and per-app instructions. For Claude Code that's a prompt to paste, so nobody needs a terminal. Next to S5 (connector detail), which these frames replace.

Answers to the open questions

Developer, 2026-10-29: all five as recommended.

  • 1 · One entry. One button, Connect an AI app, for every client: the connector URL is the same for all of them. The client is picked after connecting, with a plain segment (not accent; it's a view switch, not a mode). The “Local shim (Claude Code)” section, the build step and the config JSON leave the UI.
  • 2 · Claude Code first. CC3 and CC4 open on the Claude Code segment; the choice isn't remembered.
  • 3 · Server name health. A neutral local label in the user's Claude Code config, never the instance's product name. Command: claude mcp add --transport http --scope user health <URL>. --scope user so it isn't tied to one project folder.
  • 4 · The link is a key. A warn note under the instructions on CC3: “This link opens your records to whoever has it, while your app is open and unlocked. Disconnect turns it off.”
  • 5 · Keep it open. “Keep this app open and unlocked on one device while Claude works.” on CC3 and CC4.
  • The prompt. “Add my health records to Claude Code: run … then tell me to restart Claude Code.” It ends with the restart because Claude Code can't restart itself. The bare command stays below as the fallback.
  • One sun per view. CC1: Connect. CC2: the dialog's Connect. CC3: Copy prompt (Done drops to secondary; today's code makes Done primary). CC4 has no sun: nothing is waiting, Copy prompt is secondary.

med-ztzg. Visual design approved by Developer, 2026-10-31 (Zulip 10219), based on Developer 7933–7936, Archie 10159 and Miles 10160; release path pinned by Archie 10173; executable template bytes and delivery review remain with med-ztzg.1. Miles 10160 confirms the approved product scope.

  • Remote stays first. CC1–CC4 remote behavior is unchanged. CC5 adds Private as a secondary option for Claude Code. CC9/CC10 supersede CC4 · Local shim’s “no longer offered” presentation once the packaged helper ships.
  • Choose the destination computer. macOS/Linux/Windows selection is explicit; no phone OS guessing. The installer chooses the supported CPU architecture. One shell-appropriate prompt and terminal fallback.
  • Helper and trust. Tagged release binaries and checksum-verifying bootstrap; no source/build/manual JSON/Node step. The server relays encrypted messages; Claude/model can read requested records. A pasted prompt exposes the pairing key to Claude/transcript/config. Disconnect revokes it. Keep the app open and unlocked.
  • Feedback is literal. Copied means copied. Pairing created means configured, not installed or online. Retain selectable instructions if copy fails. Existing expiry/redeploy means reconnect, with no new lifetime promise.
  • One pairing. Confirm before replacing any current connection. New setup is explicit; no automatic mode switch.
  • No guessed installer URL. Bracketed command/release/key text in these frames is illustrative. med-ztzg.1 supplies tested immutable installer template bytes before med-ztzg.2 ships (Archie 10173). Future asset root is releases/download/mcpshim-v0.1.0 in the public repository; this draft does not claim those assets are live. Canonical registration is claude mcp add --env MEDTRACKER_MCP_CODE=<code> --transport stdio --scope user health -- <absolute-user-local-binary>. Existing health fails safely; the prompt asks before a user-scope replacement/retry, never removes local/project entries. The pairing key must never be part of a download URL or telemetry.
