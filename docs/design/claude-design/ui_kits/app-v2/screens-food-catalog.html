Food catalog hints

Epic med-5jq keeps one product per food. The add sheet and the AI review show two small things: a scanned staple can be logged as a food you already have (med-5jq.7), and questionable numbers get a quiet hint you can ignore (med-5jq.9). There are no new screens or components, and nothing blocks saving.

Inside the existing sheets

FC1 sits on F5 (a picked scan result), FC2 on F7 (AI review) and FC3 on F8 (manual entry).

Answers to the open questions

Decisions (Developer approved 2026-11-05, 15507)
  1. Scan offer (.7): two choices in place of the picked row, with your food preselected, and no extra sentence. The barcode is remembered silently, so the user is asked once per barcode either way.
  2. Branded products never get the offer. No match, or more than one candidate → F5 unchanged.
  3. Matched AI items (.9): the canonical name plus the existing Mine tag. No "renamed from" line: the user never saw the AI's own name.
  4. Flags: one quiet hint line per item, with a warn icon and fg-3 text. No chip, no row colour, no dialog, and Log and Save are never disabled. With several warnings, show only the most severe (impossible, then inconsistent, then low). After a grams edit the flag stays, because it is per 100 g.
  5. Copy, one line per kind (rendered from .8's field): impossible: "Over 900 kcal per 100 g. Check the numbers." Inconsistent: "Calories don't match the macros (≈ N)." Suspiciously low: "Only N kcal per 100 g. Check per 100 g vs total."
  6. Manual sheet: it calls the .8 domain check on blur, the same function as the response field, not a UI copy (Archie to confirm the port).
