Health write-back

From Developer and Miles (2026-11-04): write the app's own BP entries (with the pulse you noted, as a heart-rate entry: Developer 15322, med-8f4s.6) and weight entries to Health Connect and Apple Health, behind a switch that is off by default. A pulse denied on its own reads like HW4: “Writing blood pressure and weight only. Pulse (heart rate) isn’t allowed: …”; two kinds missing read “… aren’t allowed: allow them in …”. This page draws the switch and its one-line disclosure on the Health import card. One design for web, shared by both shells. Data: the Android QA vault.

Answers to the open questions

Approved by Developer (14826).

  • Where: a second switch row in the Health Connect / Apple Health card on Settings home, shown only while import is on. Turning import off also turns writing off, and the switch returns off next time; nothing writes while the row is hidden.
  • Label: “Also write my entries” (Miles' wording); the aria label names the store.
  • No description line (Developer 14826): the row is the title and the switch. Text appears only for HW3/HW4, which need an action. The disclosure lives in the privacy page and the system access sheet (med-8f4s.4).
  • Which entries: operation-based (Archie 14800): any BP or weight entry added or changed on this phone, edits of synced-in rows included; no back-fill and no opt-in date cut. Syncing alone copies nothing.
  • Refused access: switch back off + where to allow it (HW3). No dialog. Partly granted (Archie): switch stays on, the line names the missing kind (HW4). Removed later (Miles 15063): switch stays on, “Writing paused” line (HW5).
  • Unchanged: the import switch, its status line, the rest of Settings home.
