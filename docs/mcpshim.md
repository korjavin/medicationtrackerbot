# Private MCP helper: release and installation reference

The private connector runs `mcpshim` locally as Claude Code's stdio MCP server.
It exchanges encrypted `mcp_help` / `mcp_call` messages with the paired unlocked
browser through the cloud's blind relay. It requires that browser online; a
successful installation does not prove that a device is connected. `cmd/cloud`
remains the only server runtime. Existing source-built helpers and remote MCP
connectors remain supported; packaging introduces no protocol negotiation.

## Public release contract

The first helper release is **`mcpshim-v0.1.0`**. It must point to a reviewed
commit reachable from `master`. Its dedicated workflow is
`.github/workflows/release-mcpshim.yml`; ordinary application release workflows
do not run on helper tags. Normal master deployment after source merge is
unchanged. The workflow refuses an existing release and never overwrites assets
or moves tags. `make_latest=false` keeps it out of the ordinary latest product
release slot. There is no `/latest` lookup or automatic runtime download.

Every file is at the exact public, unauthenticated root:

`https://github.com/korjavin/medicationtrackerbot/releases/download/mcpshim-v0.1.0/`

| Asset | Format |
| --- | --- |
| `mcpshim_0.1.0_darwin_amd64` | Raw executable |
| `mcpshim_0.1.0_darwin_arm64` | Raw executable |
| `mcpshim_0.1.0_linux_amd64` | Raw executable |
| `mcpshim_0.1.0_linux_arm64` | Raw executable |
| `mcpshim_0.1.0_windows_amd64.exe` | Raw executable |
| `mcpshim_0.1.0_windows_arm64.exe` | Raw executable |
| `SHA256SUMS` | SHA-256 for each binary, both installers, commands and provenance |
| `install.sh`, `install.ps1` | Public nonsecret installers |
| `commands.json` | Exact POSIX/PowerShell bootstrap command bytes and installer digests |
| `provenance.json` | Version, source commit, toolchain and workflow-run link |

This source defines the contract; it does not claim these release URLs already
exist. GitHub publishers can alter releases/tags despite version pinning.

The tagged `go.mod` pins Go **1.26.5**; builds use `CGO_ENABLED=0` and stamp
`0.1.0+<full-source-commit>`. `mcpshim --version` and MCP initialize advertise
the same value. There are six cross-builds. The three native CI jobs log the
actual OS/architecture executed; they do not prove execution on all six pairs.
The downloaded native artifact is launched through SDK stdio, performs encrypted
help/call round trips through the real relay, and returns a bounded error with
the device absent. Windows installer tests run under native PowerShell.

## Install and register

Prerequisites: installed Claude Code; macOS/Linux/WSL with POSIX shell, standard
`awk`, `grep`, `cut`, `mktemp`, `curl` or `wget`, and `sha256sum` or `shasum`;
or Windows with PowerShell, `Invoke-WebRequest` and `Get-FileHash`. No GitHub
login, `gh`, Node/npm, Go, source checkout, administrator access, or PATH/profile
change is needed. WSL uses the Linux installer. Unsupported OS/CPU fails closed.

Download the pinned installer from that root, inspect it, and run:

```sh
sh ./install.sh --version 0.1.0 --pairing-code '<PAIRING_CODE>'
```

```powershell
& .\install.ps1 -Version 0.1.0 -PairingCode '<PAIRING_CODE>'
```

For copyable bootstrap commands use the release's `commands.json` **verbatim**.
It embeds each installer's actual SHA-256, downloads to temporary storage,
checks those bytes, and invokes the ABI above. Its literal `<PAIRING_CODE>`
placeholder is replaced with the pairing code generated by the browser
(`mtmcp1.` plus base64url data). Never replace it with unrelated unescaped input.
The UI must consume these published bytes/digests, not guess a Windows command
or fetch a mutable latest version. `scripts/package-mcpshim.py` generates that
contract deterministically from the actual release installers and raw assets.
Bootstrap requires `curl` on POSIX; direct installation also supports `wget`.

Installers download only public, nonsecret URLs into temporary storage, require
exactly one valid manifest entry for the selected filename, and verify SHA-256
before installing or invoking Claude. The pairing code is never sent to the
download host or written to installer temporary files, output or logs. Download,
hash, unsupported-platform and ambiguous-manifest failures do not register
anything. The final binary is promoted atomically on its destination filesystem;
an existing version is reused only when its bytes match. Unknown existing bytes
are preserved and refused. Other installed versions are retained.

User-local absolute destinations:

- POSIX: `${XDG_DATA_HOME:-$HOME/.local/share}/medtracker/mcpshim/0.1.0/mcpshim`
- Windows: `$env:LOCALAPPDATA/MedTracker/mcpshim/0.1.0/mcpshim.exe`

Registration uses the supported Claude CLI argument order (the `--env` option
is variadic, so the later `--transport` terminates its values):

```text
claude mcp add --env MEDTRACKER_MCP_CODE=<code> --transport stdio --scope user health -- <one-absolute-binary-argument>
```

An existing user-scope `health` produces a sanitized, actionable failure. To
explicitly replace **only that user entry**, retry with `--replace-user-health`
or `-ReplaceUserHealth`. This requests `claude mcp remove --scope user health`
before adding it again. If removal succeeds but adding fails, retry registration;
there is no rollback copy of the old credential. Other names and local/project
entries are never removed. Those scopes can shadow the new user entry. Reconnect
Claude after registration and keep the paired browser unlocked and online.

Claude stores `MEDTRACKER_MCP_CODE` in its normal user MCP configuration. This
is the intentional config-storage boundary, not a new secret store. A copied
command/prompt exposes the code to Claude, its model/transcript, shell history
and process arguments; local config/process readers may also recover it. The
code grants the pairing's access and is not the vault DEK. Do not paste it into
public chat, issue reports, telemetry or logs.

Unsigned executables can be blocked by Gatekeeper, antivirus, or execution
policy. These installers do not bypass those protections, change PowerShell
ExecutionPolicy, request elevation, or fall back to unverified execution. Resolve
the host's policy through its normal administrator process.

## Operator acceptance and provenance

Source PR merge alone does **not** establish a published release. Keep packaging
acceptance open until the reviewed master commit is tagged through the normal
authorized release sequence, all assets are published once, and clean downloads
from each exact unauthenticated URL pass the published hashes. Record that run,
full source SHA, asset digests, actual native OS/architecture execution limits,
and attestation verification. Live fresh-machine Claude health reads and the
browser copy-command integration are separate end-to-end acceptance evidence;
fixture/native process tests do not claim them.

The tag workflow uses GitHub's current `actions/attest@v4` mechanism, pinned to
an immutable action commit. Packaging runs with only `contents: read`, including
on pull requests. A separate **job-level tag-only** attestation job downloads
the finalized artifact with `id-token: write`, `contents: read` and
`attestations: write`; it never executes the pull request's packaging script.
Release publishing is a separate `contents: write` job which requires that
attestation job to succeed.
Attestations cover the exact downloaded binary and companion bytes. Verify a
binary manually after verifying its named checksum:

```sh
gh attestation verify ./mcpshim_0.1.0_linux_amd64 --repo korjavin/medicationtrackerbot
```

This `gh` step is optional for ordinary installation and required operator
release evidence. A checksum fetched beside an executable detects accidental
corruption; it does not authenticate a malicious publisher. Bootstrap digests
start trust at the repository/UI supplying the command. GitHub attestations
identify the repository/workflow build, not an honest publisher or an audited
binary. See [release integrity](security/release-integrity.md).

### First publication: operator sequence

These are post-merge operator instructions, not actions performed by source CI.
The operator needs authenticated repository release access, `curl`, SHA-256
tooling, and a modern GitHub CLI with `gh attestation verify` (ordinary users do
not need `gh`). Record the reviewed **merged master commit**, not the PR's
synthetic merge-ref SHA or the pre-merge branch SHA. Fetch refs without changing
the working checkout, and require that full commit to be reachable from master:

```sh
git fetch origin master --tags
reviewed_commit='<reviewed-full-master-commit>'
git merge-base --is-ancestor "$reviewed_commit" origin/master
git show --no-patch --format='%H %s' "$reviewed_commit"
git ls-remote --tags origin refs/tags/mcpshim-v0.1.0
gh api --include repos/korjavin/medicationtrackerbot/releases/tags/mcpshim-v0.1.0
```

Stop on a failed reachability check, a remote/local tag, or an existing release
(including a draft). The remote-tag query must succeed with **empty output**;
the authenticated exact-release API must return **404**, not an authentication
or network error. Confirm local `refs/tags/mcpshim-v0.1.0` is also absent. Then
create the one annotated tag without force and push only that ref:

```sh
git tag -a mcpshim-v0.1.0 "$reviewed_commit" -m 'Private MCP helper 0.1.0'
git push origin refs/tags/mcpshim-v0.1.0
```

That push starts workflow **`MCP helper release`**, file
`.github/workflows/release-mcpshim.yml`. There are **no workflow inputs**: source
validation accepts only `mcpshim-v0.1.0`, selecting version `0.1.0`; tag source
must remain master-reachable. Do not also dispatch a duplicate live run.
If a fresh run is needed before any release exists, dispatch that fixed tag,
without inputs:

```sh
gh workflow run release-mcpshim.yml --repo korjavin/medicationtrackerbot --ref mcpshim-v0.1.0
gh run list --repo korjavin/medicationtrackerbot --workflow release-mcpshim.yml --branch mcpshim-v0.1.0 --json databaseId,headSha,event,status,conclusion,url
gh run watch <release-run-id> --repo korjavin/medicationtrackerbot --exit-status
```

Require the run's `headSha` to equal `reviewed_commit` and **all** `source`, six
`build`, three `native`, `package`, `attest` and `publish` jobs to succeed.
In particular, `attest` must succeed, not skip. Expected signer workflow is
`korjavin/medicationtrackerbot/.github/workflows/release-mcpshim.yml`, certificate
identity is
`https://github.com/korjavin/medicationtrackerbot/.github/workflows/release-mcpshim.yml@refs/tags/mcpshim-v0.1.0`,
and source ref is `refs/tags/mcpshim-v0.1.0` at that reviewed commit. The publisher
creates a draft once, uploads exact assets, then publishes with `make_latest=false`;
there is no overwrite or product release operation.

In a fresh verification directory, download **without GitHub authentication**
(`curl -q` disables curl configuration), using these exact names and root:

```sh
base='https://github.com/korjavin/medicationtrackerbot/releases/download/mcpshim-v0.1.0'
for asset in SHA256SUMS install.sh install.ps1 commands.json provenance.json mcpshim_0.1.0_darwin_amd64 mcpshim_0.1.0_darwin_arm64 mcpshim_0.1.0_linux_amd64 mcpshim_0.1.0_linux_arm64 mcpshim_0.1.0_windows_amd64.exe mcpshim_0.1.0_windows_arm64.exe; do
  curl -q --fail --silent --show-error --location --proto '=https' --proto-redir '=https' --tlsv1.2 "$base/$asset" --output "$asset" || exit 1
done
sha256sum -c SHA256SUMS
```

Compare `provenance.json` fields `version=0.1.0`, `source_commit=reviewed_commit`,
`toolchain=go1.26.5`, `CGO_ENABLED=0`, and `workflow_run` with the successful
tag run. Compare `commands.json`'s version/tag/source and both installer digests
with these downloaded bytes. Execute `--version` only on native supported
OS/architecture and require exactly `mcpshim 0.1.0+<reviewed_commit>`.
Verify **each** downloaded binary and the manifest against the precise policy:

```sh
gh attestation verify ./mcpshim_0.1.0_linux_amd64 --repo korjavin/medicationtrackerbot --signer-workflow korjavin/medicationtrackerbot/.github/workflows/release-mcpshim.yml --source-ref refs/tags/mcpshim-v0.1.0 --source-digest "$reviewed_commit" --deny-self-hosted-runners
```

Repeat with the other five binary filenames and `SHA256SUMS`; save the successful
verification output. An exact certificate identity may additionally be enforced
with `--cert-identity` and the URL above. Record actual native job OS/architecture
limits separately from six cross-builds. Only after these public URL/hash/source/
attestation checks is packaging release acceptance complete; source merge or a
green workflow alone does not close it. Fresh-machine live Claude health reads
and browser copy-command acceptance remain separate end-to-end gates.

### Recovery from a failed unpublished draft

An upload failure can leave a partial draft; the workflow deliberately refuses
to overwrite or reuse it. Recovery is an explicit operator action, never an
automatic cleanup. Pause publication and ensure no concurrent publisher is
running. Inspect the failed run, the fixed tag's full source commit and the
release metadata:

```sh
gh api repos/korjavin/medicationtrackerbot/releases/tags/mcpshim-v0.1.0 --jq '{id,draft,tag_name,target_commitish,html_url,assets:[.assets[]|{name,id,size,digest}]}'
```

Proceed only if the operator has verified this is the failed run's **still
unpublished draft**, with `draft: true`, and it has **never been published**.
If it is published, has ever been published, or ownership/state is uncertain,
stop: do not delete the public release or overwrite its assets; use a new
reviewed version. For a verified never-published draft only, deliberately delete
that draft by its inspected release ID, preserving the tag:

```sh
gh api --method DELETE repos/korjavin/medicationtrackerbot/releases/<verified-draft-release-id>
```

Do not delete or move the tag, use `--cleanup-tag`, or repair assets in place.
After correcting a transient delivery problem, start a fresh run against the
same fixed reviewed tag (which repeats source, six builds, native proof,
packaging and attestations):

```sh
gh workflow run release-mcpshim.yml --repo korjavin/medicationtrackerbot --ref mcpshim-v0.1.0
```

A source or workflow defect requiring a different tagged commit requires a new
reviewed version instead. Complete the exact public download/digest/attestation
acceptance after recovery; a successful retry alone is not that evidence.
